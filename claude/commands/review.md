# /review — RobotBuddy 代码与架构审查

## 用途

对 RobotBuddy 固件代码进行多维度审查，确保代码质量、内存安全、实时性正确。

## 适用场景

- PR 代码审查
- 发布前质量门禁
- 架构重构后验证
- 性能问题排查

## 工作流

```
第 1 阶段：自动检查
├── 1.1 编译检查：idf.py build — 0 error, 0 warning
├── 1.2 静态分析：对照 standards/embedded-coding.md
├── 1.3 对照 checklists/pre-commit.md 逐项检查
└── 1.4 输出：自动检查报告

第 2 阶段：架构审查
├── 2.1 FreeRTOS 任务优先级审计 — 无优先级反转
├── 2.2 事件总线消息流审计 — 无死锁/消息丢失
├── 2.3 内存布局审计 — PSRAM/IRAM/DRAM 使用合理
├── 2.4 中断延迟审计 — ISR 执行时间 < 10μs
└── 2.5 输出：架构审查报告

第 3 阶段：代码质量审查
├── 3.1 命名规范：函数 snake_case、类型 PascalCase、宏 UPPER_CASE
├── 3.2 错误处理：所有 API 返回值被检查
├── 3.3 资源管理：malloc/free 成对，文件句柄闭合
├── 3.4 并发安全：共享资源有互斥锁/关中断保护
├── 3.5 日志完整：关键路径有 ESP_LOGI/ESP_LOGE
└── 3.6 输出：代码质量报告

第 4 阶段：专项审查
├── 4.1 内存安全：
│   ├── 栈溢出检测（uxTaskGetStackHighWaterMark ≥ 256 bytes）
│   ├── 堆碎片检测（heap_caps_get_free_size）
│   ├── 无野指针/Use-After-Free
│   └── Ring Buffer 边界检查
├── 4.2 实时性：
│   ├── 音频任务无丢帧（≥16kHz 连续采样）
│   ├── 电机 PID 控制周期稳定（100Hz ± 5%）
│   └── SPI 刷新帧率稳定（30FPS ± 10%）
├── 4.3 功耗：
│   ├── 无忙等（busy-wait 转 event-driven）
│   ├── WiFi 休眠策略正确
│   └── 空闲时屏幕进入低功耗模式
└── 4.4 输出：专项审查报告

第 5 阶段：汇总
├── 5.1 按严重程度分级：🔴Critical / 🟡Warning / 🔵Suggestion
├── 5.2 每个问题附带：文件:行号 + 问题描述 + 修复建议
└── 5.3 输出：审查汇总报告
```

## 审查维度矩阵

| 维度 | 权重 | 通过标准 |
|------|------|---------|
| 编译通过 | 必须 | 0 error, 0 warning |
| 编码规范 | 高 | ≥90% 合规 |
| 内存安全 | 必须 | 无泄漏/溢出 |
| 并发安全 | 必须 | 无竞态/死锁 |
| 实时性 | 高 | 满足时序要求 |
| 错误处理 | 中 | 所有路径有处理 |
| 日志完整 | 中 | 关键路径可追溯 |
| 功耗合理 | 低 | 无极端浪费 |

## 输出格式

输出报告到docs目录下

```markdown
## 审查报告 — [模块名]

### 🔴 Critical (必须修复)
- `file.c:123` — 问题描述 → 修复建议

### 🟡 Warning (建议修复)
- `file.c:456` — 问题描述 → 修复建议

### 🔵 Suggestion (可选优化)
- `file.c:789` — 优化建议

### 指标汇总
- Stack free: 512 bytes ✅
- Heap free: 1.2MB ✅
- Max ISR time: 3μs ✅
```
