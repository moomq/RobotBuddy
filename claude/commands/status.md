# /status — RobotBuddy 项目状态一览

## 用途

快速查看 RobotBuddy 项目的当前状态，包括模块完成度、编译状态、硬件进度和待办事项。

## 适用场景

- 每日开发开始前的项目状态确认
- 模块开发进度跟踪
- 发布前的功能完成度检查
- 新成员了解项目进展

## 工作流

```
第 1 阶段：项目概况
├── 1.1 Git 状态: 当前分支、最近提交、未提交修改
├── 1.2 固件版本: app_version.h 中的版本号
├── 1.3 目标产品版本: V1.0 MVP / V2.0 / V3.0
└── 1.4 输出：项目基础信息

第 2 阶段：模块完成度
├── 2.1 扫描 firmware/ 目录结构
├── 2.2 检查各模块目录是否存在:
│   ├── drivers/ — 硬件驱动层
│   │   ├── display/ (ST7789)
│   │   ├── audio/ (INMP441 + MAX98357A)
│   │   ├── motion/ (DRV8833)
│   │   ├── sensor/ (MPU6050 + IR)
│   │   └── power/ (TP4056 + Battery)
│   ├── services/ — 服务层
│   │   ├── audio_manager/
│   │   ├── display_manager/
│   │   ├── motion_manager/
│   │   ├── cloud_manager/
│   │   ├── sensor_manager/
│   │   └── event_bus/
│   ├── app/ — 应用层
│   │   ├── emotion_engine/
│   │   ├── behavior_mgr/
│   │   └── ai_dialog/
│   └── system/ — 系统组件
│       ├── sysmon/
│       ├── power_mgr/
│       └── ota_service/
├── 2.3 对每个模块评估:
│   ├── 📁 目录已创建
│   ├── 📝 骨架代码存在
│   ├── ✅ 基本功能实现
│   ├── 🧪 测试覆盖
│   └── 📖 文档完成
└── 2.4 输出：模块完成度矩阵

第 3 阶段：编译状态
├── 3.1 尝试构建: idf.py build
├── 3.2 固件大小: idf.py size-components
├── 3.3 分区使用: idf.py partition-table
├── 3.4 内存预算:
│   ├── Flash 使用 / 16MB
│   ├── PSRAM 使用 / 8MB
│   └── DRAM 使用 / 512KB
└── 3.5 输出：编译和资源状态

第 4 阶段：硬件进度
├── 4.1 PCB 设计状态: 未开始 / 设计中 / 已下单 / 已到手
├── 4.2 外壳 3D 打印: 未开始 / 建模中 / 打印中 / 已完成
├── 4.3 组件采购: 对照 BOM 检查各组件到位情况
└── 4.4 输出：硬件进度

第 5 阶段：待办事项
├── 5.1 代码中的 TODO/FIXME 统计
├── 5.2 未通过的测试用例
├── 5.3 PRD 中未实现的功能（按 P0/P1/P2 分组）
└── 5.4 输出：待办清单
```

## 注意事项

- 编译状态检查仅在 firmware/ 目录和 sdkconfig 存在时可用
- 模块完成度为估算值，需结合实际测试结果判断
- TODO/FIXME 统计使用 grep 扫描源码，可能有误报
- 硬件进度需要手动更新（无法自动检测）
