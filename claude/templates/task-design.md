> 用途：每新增一个 FreeRTOS Task/Service 时，使用此模板记录设计决策

## 基本信息

| 项目 | 值 |
|------|-----|
| **Task 名称** | `_task` |
| **所属模块** | （如 audio / display / motion / cloud / behavior） |
| **优先级** | 0 (最低) ~ 8 (最高) |
| **栈大小** | KB（最小 1KB） |
| **运行核心** | Core 0 (WiFi/蓝牙) / Core 1 (应用) |
| **周期** | 事件驱动 / 周期性 ___ms |
| **负责人** | |

---

## 优先级参考

```
优先级分配表:
├── 8: audio_capture (I2S 采集，不可中断)
├── 7: audio_playback (I2S 播放，不可中断)
├── 6: display_refresh (30FPS 显示刷新)
├── 5: emotion_engine (表情动画计算)
├── 4: cloud_comm (云端通信，含 TLS)
├── 3: motion_ctrl (PID 100Hz 控制)
├── 2: sensor_poll (传感器轮询)
├── 1: behavior_mgr (行为决策)
├── 1: ota_service (OTA 升级)
└── 0: idle_monitor (空闲检测)
```

## 测试要点

- [ ] 任务创建和删除正常
- [ ] 事件接收和发布正常
- [ ] 高负载下栈水位安全 (>30% 余量)
- [ ] 错误场景下的优雅恢复
- [ ] 与其他任务的通信无死锁
- [ ] 看门狗喂狗正常
- [ ] 长时间运行无内存泄漏

## 日志规范

```c
#define TAG "[task_name]"

// 日志级别使用规范:
// ESP_LOGE: 错误，需要关注和处理
// ESP_LOGW: 警告，可能影响功能但不致命
// ESP_LOGI: 重要信息，初始化/状态变化/关键路径
// ESP_LOGD: 调试信息，开发阶段使用
// ESP_LOGV: 详细追踪，仅深度调试时开启
```
