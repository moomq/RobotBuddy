## 1. 测试策略

### 1.1 测试金字塔

```
                    /\
                   /  \          L4: 验收测试 (手动)
                  /    \         开发者实机使用 1 周
                 /------\        ─────────────────────
                / L3: 集成 \      完整系统联调
               /   测试     \     每周自动/发布前手动
              /──────────────\
             / L2: HIL 测试  \   真实硬件验证
            /  (ESP32 + 外设)  \   每次 PR / 每日
           /────────────────────\
          / L1: 单元测试 (Unity)  \ PC + Mock
         /________________________\ 每次 commit 自动
```

### 1.2 覆盖率目标

| 级别 | 目标覆盖率 | 运行环境 | 频率 |
|------|----------|---------|------|
| L1 单元 | ≥ 80% 行覆盖 | PC (Unity + CMock) | 每次 commit |
| L2 HIL | 关键路径 100% | ESP32-S3 真实硬件 | 每次 PR |
| L3 集成 | 全链路验证 | 完整机器人 | 每周 / 发布前 |
| L4 验收 | 所有 AC | 最终产品 | 版本发布前 |

## 4. L3 系统集成测试

### 4.1 端到端场景测试

#### 场景 1: 语音对话全链路

```
步骤:
1. 按下唤醒按钮或说 "Hey Buddy"
2. 说出: "什么是 Python 装饰器"
3. 等待 ASR 转文字
4. 等待 LLM 生成回复
5. 等待 TTS 播放

验证:
- ASR 识别率 > 80%
- 表情切换: IDLE → LISTENING → THINKING → ANSWERING → IDLE
- TTS 播放完整
- 端到端延迟 < 5 秒 (网络正常)
```

#### 场景 2: 避障与运动

```
步骤:
1. 发送前进命令
2. 在前方放置障碍物
3. 观察机器人反应
4. 在桌面边缘测试

验证:
- 正常前进速度 ≈ 0.2 m/s
- 避障停止 < 10ms
- 边缘检测后退
- 表情切换为 WARNING
```

#### 场景 3: WiFi 断线恢复

```
步骤:
1. 正常连接 WiFi
2. 关闭路由器
3. 等待 10 秒
4. 重新开启路由器

验证:
- WiFi 断开后表情切换为 ERROR
- 重连成功 < 30 秒
- AI 对话功能恢复
- 无内存泄漏
```

#### 场景 4: 长时间运行稳定性

```
步骤:
1. 启动所有功能
2. 每 5 分钟执行一次语音交互
3. 持续运行 24 小时

验证:
- 无崩溃/重启
- 内存使用稳定 (无泄漏)
- 所有任务栈水位安全 (≥512 bytes free)
- CPU 使用率 < 80%
```

## 5. 压力与稳定性测试

### 5.1 24小时压力测试

| 阶段 | 时长 | 操作 | 检查项 |
|------|------|------|--------|
| 启动 | 0-3s | 冷启动 | 开机时间 < 3s |
| 空闲 | 1h | 待机表情 | 内存稳定, FPS ≥ 30 |
| 语音 | 2h | 每5分钟对话一次 | 无内存泄漏, 无崩溃 |
| 运动 | 1h | 随机运动命令 | 电机正常, 无堵转 |
| WiFi | 1h | 断线重连测试 | 重连 < 30s |
| 传感器 | 1h | 遮挡/移动测试 | 所有传感器响应 |
| 全功能 | 18h | 综合运行 | 栈水位, 堆, CPU |

### 5.2 内存泄漏检测

```
每30分钟记录:
- heap_free_dram (应稳定, 不持续下降)
- heap_free_psram (应稳定)
- 各任务栈水位 (应 ≥ 512 bytes)
- 事件队列深度 (应 ≤ 队列容量的50%)
- WiFi 连接状态
```

### 6.2 CI/CD

```yaml
# .github/workflows/test.yml
name: RobotBuddy Tests
on: [push, pull_request]

jobs:
  unit-tests:
    runs-on: ubuntu-latest
    container: espressif/idf:release-v5.1
    steps:
      - uses: actions/checkout@v4
      - name: Build firmware
        run: cd firmware && idf.py build
      - name: Run unit tests
        run: cd firmware/build && ctest --output-on-failure

  hil-tests:
    runs-on: [self-hosted, esp32-s3]
    if: github.event_name == 'pull_request'
    steps:
      - uses: actions/checkout@v4
      - name: Flash and test
        run: |
          cd firmware
          idf.py build
          idf.py flash monitor &
          python ../scripts/run_hil_tests.py
```
