# 桌面 AI 开发助手机器人（ESP32 方案）

## 产品功能需求文档（PRD V2.0）

---

## 产品定位

### 产品名称

- **RobotBuddy**

### 一句话定位

> 一款放在桌面的、有"表情"和"声音"的 **AI 编程助手机器人**，能像 Claude Desktop Buddy 一样陪你写代码、Debug、学技术。

### 与 V1.0（情感陪伴机器人）的核心差异

| 维度 | V1.0 情感陪伴 | V2.0 AI 开发助手 |
|------|--------------|-----------------|
| 核心场景 | 日常陪伴、聊天 | **编程辅助、技术问答** |
| 屏幕用途 | 表情动画 | **表情 + 代码片段 + 状态提示** |
| 语音交互 | 闲聊为主 | **技术讨论、代码讲解** |
| AI 能力 | 通用对话 | **代码理解、Debug、架构建议** |
| 目标用户 | 普通消费者 | **开发者 / 程序员** |

## 外观设计（基于参考图片 robot.PNG）

### 整体造型

通过图像分析，机器人外观特征如下：

| 特征 | 描述 |
|------|------|
| **整体形状** | 圆润蛋形 / 椭圆形机身，左右对称 |
| **主色调** | 暖米白 / 奶油色机身（RGB ~175, 155, 135） |
| **表面质感** | 光滑亮面塑料，有高光反射 |
| **头部** | 无独立头部，机身正面上方嵌入屏幕 |
| **天线/耳朵** | 无突出天线或耳朵结构，顶部圆滑 |
| **按钮** | 正面无可见物理按钮（隐藏式或背置设计） |

### 屏幕 / 面部

这是机器人最显著的特征：

| 特征 | 描述 |
|------|------|
| **屏幕位置** | 机身正面上方，约占机身高度 25% |
| **屏幕形状** | 矩形圆角屏幕，深色边框 |
| **显示内容** | 一对**圆形大眼睛**，青色/蓝绿色虹膜 |
| **眼睛特征** | 深色瞳孔 + 青色虹膜 + 白色高光点（光泽感） |
| **屏幕背景** | 深色/黑色背景，突出眼睛显示 |
| **屏幕类型推断** | 圆形或方形 IPS LCD，≥240x240 分辨率 |

### 底盘 / 移动

| 特征 | 描述 |
|------|------|
| **驱动方式** | 双轮差速驱动 |
| **轮子位置** | 机身底部两侧可见深色轮子 |
| **底盘结构** | 双轮 + 底盘支撑结构 |
| **移动能力** | 前进、后退、转向、原地旋转 |

## 产品目标

打造一台：

- **能"看代码"** — 屏幕可显示代码片段、运行状态、错误提示
- **能"聊技术"** — 语音交互专注于编程问答、技术讨论
- **能"表达状态"** — 眼睛动画反馈编译/运行/调试状态
- **能"动"** — 桌面移动、跟随提醒
- **能"联网协作"** — 对接 Claude/OpenAI/DeepSeek 等云端 AI

的桌面级 AI 编程助手机器人。

## 用户场景

### 场景一：代码讲解

```
开发者："帮我解释一下这段 Python 装饰器的原理"
    ↓
机器人：云端 LLM 理解问题 → TTS 语音讲解
    ↓
屏幕：眼睛呈现"思考"动画 → "讲解"动画
```

### 场景二：Bug 调试助手

```
开发者："这段代码为什么报 NullPointerException？"
    ↓
机器人：语音接收 → 云端 AI 分析 → 给出可能原因和修复建议
    ↓
屏幕：显示警告表情（黄色眼睛 + 感叹号动画）
```

### 场景三：架构建议

```
开发者："我现在有 3 个微服务，应该用什么消息队列？"
    ↓
机器人：理解上下文 → 对比 Kafka / RabbitMQ / Redis Stream
    ↓
屏幕：眼睛呈现"认真分析"动画 + 分段语音回复
```

### 场景四：番茄钟 / 专注陪伴

```
开发者：开始 Coding
    ↓
机器人：进入"专注模式" — 屏幕显示计时器 / 眼睛微闭
    ↓
25 分钟后：眼睛闪烁提醒 → 语音"该休息一下了"
```

### 场景五：代码编译状态反馈

```
开发者：执行 npm run build
    ↓
通过 WiFi 接收编译结果 → 屏幕实时反馈
    ↓
成功：绿色笑眼 + "Build Success!"
失败：红色怒眼 + 错误计数
```

### 场景六：Git 状态提醒

```
定时检查 Git 仓库状态
    ↓
有待提交：眼睛变黄色 → "你有 3 个文件还没 commit 哦"
有冲突：眼睛变红色 → "main.cpp 有合并冲突！"
```

## 核心功能需求

### 1. 显示系统

#### 功能列表

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 表情显示 | 多种眼睛动画（开心/思考/困惑/警告/睡眠） | P0 |
| 代码滚动 | 简短代码片段滚动显示 | P1 |
| 状态图标 | 编译中/成功/失败/Git状态 图标 | P0 |
| 动画播放 | 眨眼、呼吸、Loading 旋转等 | P0 |
| 文字滚动 | 错误信息、提示信息横向滚动 | P1 |
| 番茄钟 | 倒计时数字显示 | P2 |

#### 技术需求

| 项目 | 需求 |
|------|------|
| 屏幕类型 | IPS LCD（推荐 ST7789 驱动） |
| 尺寸 | 1.69 ~ 2.4 寸圆形或方形 |
| 分辨率 | ≥ 240×240 |
| 接口 | SPI |
| 刷新率 | ≥ 30 FPS |
| 颜色 | ≥ 65K 色（16bit） |

#### 表情状态机（开发场景适配）

```
表情状态：
├── IDLE         — 待机（眼睛微动、眨眼）
├── LISTENING    — 聆听（眼睛放大、波纹动画）
├── THINKING     — 思考（眼睛左右移动、Loading 圈）
├── ANSWERING    — 说话（眼睛随语音节奏变化）
├── HAPPY        — 编译成功 / 测试通过（弯月笑眼 ✨）
├── CONFUSED     — 没听懂 / 不确定（歪头 + 问号）
├── WARNING      — 编译警告 / Git 待处理（黄色闪烁）
├── ERROR        — 编译失败 / 报错（红色怒眼 ❌）
├── FOCUS        — 专注模式（眼睛微闭 / 计时器）
├── SLEEP        — 长时间无操作（闭眼休眠）
└── EXCITED      — 新消息 / 新功能提示（跳动画）
```

| 场景 | 行为 |

| 番茄钟提醒 | 移动到用户面前摇摆 |

## 硬件需求

### 主控芯片

| 项目 | 选型 |
|------|------|
| **主控** | **ESP32-S3** |
| Flash | 16 MB |
| PSRAM | 8 MB（OTCA 模式） |
| 主频 | 240 MHz（双核 LX7） |
| WiFi | 802.11 b/g/n, 2.4 GHz |
| BLE | Bluetooth 5.0 LE |
| USB | USB OTG（支持 USB-JTAG 调试） |

**选型理由：**
- 双核 + SIMD 指令，适合音频处理和屏幕驱动
- 内置 PSRAM 支持，可缓冲大音频数据
- 原生 USB 调试，开发体验好
- ESP-IDF 生态成熟，AI 语音相关组件丰富

### 音频系统

| 组件 | 型号 | 接口 | 备注 |
|------|------|------|------|
| MEMS 麦克风 | **INMP441** | I2S | 全向、低噪声、数字输出 |
| 音频功放 | **MAX98357A** | I2S | 3W, D 类功放 |
| 扬声器 | 3W 全频喇叭 | — | Φ28mm 或 Φ36mm |

### 显示系统

| 组件 | 型号 | 接口 | 备注 |
|------|------|------|------|
| 屏幕 | **ST7789** IPS | SPI (40MHz) | 240×240, 1.69~2.4寸 |
| 可选升级 | GC9A01 | SPI | 圆形屏, 240×240 |

### 电机系统

| 组件 | 型号 | 备注 |
|------|------|------|
| 减速电机 ×2 | **N20 微型减速电机** | 6V, ~200 RPM |
| 电机驱动 | **DRV8833** | 双路 H 桥, 低功耗 |
| 替代驱动 | TB6612FNG | 更大电流 |

### 电源系统

| 组件 | 型号/参数 | 备注 |
|------|----------|------|
| 电池 | **18650 锂电池** | 3.7V, 2000~3400 mAh |
| 充电管理 | **TP4056** + 保护板 | Type-C 接口, 1A 充电 |
| 升压电路 | MT3608 / SY8088 | 升压至 5V 供 ESP32 |
| 电量检测 | 电阻分压 + ADC | 通过 GPIO 读取电池电压 |

### 传感器汇总

| 类别 | 传感器 | 数量 | 用途 |
|------|--------|------|------|
| 必选 | MPU6050 (IMU) | 1 | 姿态/跌落检测 |
| 必选 | TCRT5000 (红外) | 2 | 前方避障 |
| 必选 | ITR20001 (红外) | 2 | 边缘防跌落 |
| 可选 | VL53L0X (TOF) | 2 | 精确避障 |
| 可选 | 电容触摸 | 1 | 头顶互动 |
| 可选 | BH1750 | 1 | 环境光检测 |

```
│  │Manager │ │Parser  │ │ Machine          │      │
│  └────────┘ └────────┘ └──────────────────┘      │
├──────────────────────────────────────────────────┤
│                    驱动层 (Drivers)                │
│                                                    │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐     │
│  │SPI │ │I2S │ │PWM │ │I2C │ │GPIO│ │ADC │     │
│  └────┘ └────┘ └────┘ └────┘ └────┘ └────┘     │
└──────────────────────────────────────────────────┘
```

### FreeRTOS 任务划分

| 任务名 | 优先级 | 栈大小 | 周期 | 职责 |
|--------|--------|--------|------|------|
| audio_capture | 高 (8) | 8KB | 事件驱动 | I2S 麦克风采集，音频缓冲 |
| audio_playback | 高 (7) | 8KB | 事件驱动 | I2S 扬声器播放，音频流输出 |
| display_refresh | 高 (6) | 4KB | 33ms (30FPS) | SPI 屏幕刷新，帧缓冲推送 |
| emotion_engine | 中 (5) | 4KB | 50ms | 表情动画状态机，帧生成 |
| cloud_comm | 中 (4) | 12KB | 事件驱动 | WiFi HTTP/WS 通信，云端 AI 交互 |
| motion_ctrl | 中 (3) | 2KB | 10ms (100Hz) | 电机 PID 控制，编码器读取 |
| sensor_poll | 低 (2) | 2KB | 50ms | IMU/红外/TOF 传感器轮询 |
| behavior_mgr | 低 (1) | 4KB | 100ms | 行为决策，状态切换 |
| ota_service | 低 (1) | 8KB | 按需 | OTA 固件下载和升级 |
| idle_monitor | 最低 (0) | 1KB | 1s | 空闲检测，自动休眠 |

### 通信机制

```
Event Bus (事件总线)
    ↓
┌──────────────────────────────────────────┐
│  事件生产者         事件消费者             │
│                                           │
│  sensor_poll  ──→  behavior_mgr          │
│  cloud_comm   ──→  emotion_engine        │
│  audio_capture ──→ cloud_comm            │
│  cloud_comm   ──→  audio_playback        │
│  behavior_mgr ──→  motion_ctrl           │
│  behavior_mgr ──→  emotion_engine        │
│  emotion_engine ─→ display_refresh       │
└──────────────────────────────────────────┘

实现方式：
├── FreeRTOS Queue    — 任务间消息传递
├── Event Group       — 多事件同步
└── Ring Buffer       — 音频流数据
```

## 技术难点与风险

### 难点分析

| 难点 | 说明 | 缓解方案 |
|------|------|---------|
| **低延迟语音** | ESP32→云端→TTS→播放 全链路延迟 | WebSocket 流式传输 + 音频预缓冲 |
| **表情同步** | 语音播放与眼睛动画精确同步 | 音频 RMS 能量检测 → 驱动嘴巴动画 |
| **编程场景理解** | LLM 需要持续跟进技术上下文 | 云端保存对话历史 Session |
| **WiFi 稳定性** | 音频流对网络质量敏感 | 自动重连 + 本地缓存 + 离线模式 |
| **功耗平衡** | 屏幕 + WiFi + 电机同时工作耗电大 | 动态调频 + 屏幕休眠策略 |
| **结构设计** | 双轮平衡 + 重心 + 桌面防跌 | 低重心布局 + 多红外传感器 |

### 最大难点

> **不是硬件，不是运动，而是——"自然的 AI 编程交互体验"**

具体包括：
1. 语音→文字→代码理解→生成回答→TTS 的全链路低延迟
2. 编程话题的上下文保持和深度讨论
3. 编译/调试状态与表情动画的实时联动
4. "像有一个真正的编程伙伴坐在桌上"的沉浸感
