### FR-01: 显示系统 — 表情引擎

#### 1. 功能描述

| 项 | 说明 |
|----|------|
| **做什么** | 在 ST7789 240×240 IPS LCD 上渲染机器人眼睛表情动画 |
| **触发条件** | 行为系统下发表情状态变更事件；定时器驱动眨眼动画 |
| **期望结果** | 屏幕以 ≥30 FPS 显示当前表情，状态切换时 ≤50ms 过渡 |

#### 2. MVP 表情清单

| 表情 | 视觉描述 | 触发场景 |
|------|---------|---------|
| IDLE | 睁眼微动，定时眨眼 | 默认待机状态 |
| LISTENING | 眼睛放大，轻微波纹 | 检测到唤醒词/语音输入 |
| THINKING | 眼睛左右移动，Loading 旋转 | 等待 AI 回复中 |
| HAPPY | 弯月笑眼 ✨ | 编译成功/正面反馈 |
| ERROR | 红色怒眼 ❌ | 编译失败/错误状态 |
| SLEEP | 闭眼，缓慢呼吸动画 | 长时间无操作/低电量 |

#### 3. 硬件依赖

| 硬件 | 型号 | 接口 | 状态 | 能力评估 |
|------|------|------|------|---------|
| LCD | ST7789 IPS | SPI @ 40MHz | BSP 已初始化 | 240×240×2B = 115,200 字节/帧，30FPS = 3.46MB/s，SPI 40MHz 可承载 |
| 背光 | GPIO_NUM_40 | GPIO | BSP 已初始化 | PWM 调光后续可扩展 |

**帧缓冲内存分析：**

| 方案 | 内存占用 | FPS | 推荐度 |
|------|---------|-----|--------|
| 全帧缓冲 (PSRAM) | 115,200 B ≈ 113 KB | ≥30 | ⭐⭐⭐ MVP 推荐 |
| 半帧双缓冲 (PSRAM) | 57,600 B × 2 ≈ 113 KB | ≥30 | ⭐⭐ 无闪烁 |
| 局部更新 (SRAM) | ~10 KB | 15-20 | ⭐ 仅适合静态 |

**假设：** 使用 PSRAM 全帧缓冲方案，单缓冲起步，如有闪烁再改双缓冲。

#### 4. FreeRTOS 任务影响

| 项 | 说明 |
|----|------|
| 任务名 | `display_task` |
| 优先级 | 6 (高) |
| 栈大小 | 4 KB |
| 核心 | Core 1 (不与 WiFi/音频争抢) |
| 周期 | 33ms (30 FPS) |
| 输入 Queue | `xQueueDisplay` — 接收表情状态变更命令 |
| 输出 | SPI 总线写入帧数据 |

#### 5. 云/网络依赖

无直接依赖。表情状态由行为系统本地决策，不依赖云端。

#### 6. 异常处理

| 异常 | 处理策略 |
|------|---------|
| SPI 传输失败 | 重试 3 次，仍失败则置 `display_error` 标志，行为系统切换到 ERROR 表情 |
| 帧缓冲分配失败 | 降级为 16 色低分辨率模式 (120×120)，保证基本表情可见 |
| 表情状态 Queue 满 | 丢弃最旧命令，保留最新状态 |
| 背光 GPIO 故障 | 强制开启背光，日志告警 |

#### 7. 验收条件

| # | 条件 | 测试方法 |
|---|------|---------|
| AC-01 | 6 种表情均能正确显示，无明显撕裂 | 逐个触发每种表情，目视检查 |
| AC-02 | 帧率 ≥ 30 FPS | 测量 `display_task` 每秒完成帧数 |
| AC-03 | 状态切换延迟 ≤ 50ms | 从发送 Queue 命令到屏幕变化的计时 |
| AC-04 | 眨眼动画自然流畅 | 目视检查无卡顿 |
| AC-05 | PSRAM 帧缓冲分配成功 | 日志确认分配地址和大小 |
| AC-06 | SPI 传输无错误 | 监控 SPI 错误计数器 |

### FR-02: 语音交互系统

#### 1. 功能描述

| 项 | 说明 |
|----|------|
| **做什么** | 完整的语音交互管道：麦克风采集 → 云端 ASR → LLM → TTS → 扬声器播放 |
| **触发条件** | 唤醒词检测 ("Hey Buddy") / 按钮触发 / 行为系统指令 |
| **期望结果** | 从用户说完话到机器人开始播放回复，总延迟 < 1.5 秒 |

#### 2. 语音交互流程

```
用户语音
  ↓
[INMP441 麦克风] → I2S 采集 (16kHz/16bit/单声道)
  ↓
[audio_capture_task] → Ring Buffer (PSRAM, ~32KB)
  ↓
[cloud_task] → HTTP/WS 上传音频到云端 ASR (Whisper)
  ↓
云端 LLM (Claude/GPT) → 文本回复
  ↓
云端 TTS (Edge-TTS/自建) → 音频流回传
  ↓
[audio_playback_task] → I2S 输出到 MAX98357A 功放
  ↓
[扬声器] → 语音播放
```

#### 3. 硬件依赖

| 硬件 | 型号 | 接口 | 状态 | 能力评估 |
|------|------|------|------|---------|
| 麦克风 | INMP441 | I2S RX | BSP 已初始化 | 16kHz/16bit/单声道，满足语音质量要求 |
| 功放 | MAX98357A | I2S TX | BSP 已初始化 | 3W D类功放，音量足够桌面使用 |
| 扬声器 | 3W Φ28mm | — | 未连接 | 需确认喇叭阻抗匹配 |

**音频缓冲内存分析：**

| 缓冲区 | 大小 | 位置 | 说明 |
|--------|------|------|------|
| 采集缓冲 (RX) | 32 KB (2×16KB 双缓冲) | PSRAM | 存储 1 秒音频 @16kHz/16bit |
| 发送缓冲 | 16 KB | PSRAM | HTTP 分块上传缓冲 |
| 接收缓冲 (TX) | 64 KB | PSRAM | TTS 音频流接收，支持 2 秒预缓冲 |
| 播放缓冲 | 8 KB (2×4KB 双缓冲) | SRAM | I2S DMA 播放缓冲 |

**总音频内存估算：~120 KB PSRAM + ~8 KB SRAM**

#### 4. FreeRTOS 任务影响

| 任务名 | 优先级 | 栈大小 | 核心 | 职责 |
|--------|--------|--------|------|------|
| `audio_capture_task` | 8 (最高) | 8 KB | Core 0 | I2S 麦克风采集，写入 Ring Buffer |
| `audio_playback_task` | 7 | 8 KB | Core 0 | I2S 扬声器播放，从 Ring Buffer 读取 |
| `cloud_task` (部分) | 4 | 12 KB | Core 0 | HTTP/WS 通信，音频上传和 TTS 下载 |

**通信机制：**

| 机制 | 用途 | 大小 |
|------|------|------|
| `xQueueAudioCmd` | 音频命令 (开始/停止录音/播放) | 10 槽 |
| `xRingBufferAudio` | 音频数据流 (采集→云端/云端→播放) | 32 KB |
| `xEventGroupAudio` | 音频状态 (录音中/播放中/空闲) | — |

#### 5. 云/网络依赖

**强依赖 WiFi：**

| 云端服务 | 用途 | 协议 | 备选方案 |
|----------|------|------|---------|
| Whisper ASR | 语音→文字 | HTTP POST (multipart) | 本地 ESP-SR 关键词识别 |
| Claude/GPT LLM | 编程对话 | HTTP POST (JSON) | DeepSeek API |
| Edge-TTS | 文字→语音 | HTTP 流式 | 自建 TTS 服务 |

**离线降级：**
- WiFi 断开时：本地唤醒词 (ESP-SR) + 预设回复 + ERROR 表情
- API 超时时：重试 3 次，每次超时 10 秒，仍失败则提示"网络不好"

#### 6. 异常处理

| 异常 | 处理策略 |
|------|---------|
| WiFi 断开 | 暂停语音交互，显示 ERROR 表情，WiFi 恢复后自动重连 |
| ASR 识别失败 | 提示"没听清，请再说一次"，回到 LISTENING 状态 |
| LLM API 超时 (>30s) | 提示"思考时间太长了"，回到 IDLE |
| TTS 生成失败 | 直接在屏幕显示文字回复（降级方案） |
| I2S 采集错误 | 重启 I2S 通道，重试 3 次 |
| 扬声器无声 | 检查 I2S TX 通道状态，尝试重新初始化 |
| PSRAM 缓冲分配失败 | 降低采样率到 8kHz，减少缓冲大小 |

#### 7. 验收条件

| # | 条件 | 测试方法 |
|---|------|---------|
| AC-01 | 语音采集正常，16kHz/16bit | 录制 5 秒音频到 SD/SPIFFS，PC 播放验证 |
| AC-02 | 云端 ASR 识别率 ≥ 80% (安静环境) | 10 句标准测试语，统计正确率 |
| AC-03 | 端到端延迟 < 1.5 秒 | 从说完话到开始听到回复计时 |
| AC-04 | 扬声器播放清晰，无明显噪音 | 听感测试 |
| AC-05 | WiFi 断开时优雅降级 | 关闭 AP 测试，确认 ERROR 表情+提示 |
| AC-06 | 同时录音+播放不冲突 | 全双工测试 |

### FR-03: 移动控制系统

#### 1. 功能描述

| 项 | 说明 |
|----|------|
| **做什么** | 驱动双轮差速电机，实现前进/后退/左转/右转/原地旋转 |
| **触发条件** | 行为系统下发运动命令 |
| **期望结果** | 电机响应延迟 ≤ 10ms，最大速度 ≤ 0.3 m/s |

#### 2. MVP 运动命令

| 命令 | 参数 | 说明 |
|------|------|------|
| `MOVE_FORWARD` | speed (0-255) | 前进 |
| `MOVE_BACKWARD` | speed (0-255) | 后退 |
| `TURN_LEFT` | speed (0-255) | 左转 |
| `TURN_RIGHT` | speed (0-255) | 右转 |
| `ROTATE` | angle (±360°) | 原地旋转 |
| `STOP` | — | 急停 |

#### 3. 硬件依赖

| 硬件 | 型号 | 接口 | 状态 | 能力评估 |
|------|------|------|------|---------|
| 电机驱动 | DRV8833 | LEDC PWM | BSP 已初始化 | 双路 H 桥，支持正/反/制动/滑行 |
| 电机 | N20 减速 | — | 未连接 | 6V/200RPM，桌面速度足够 |

**PWM 配置（已定义在 bsp_pinmap.h）：**

| 参数 | 值 | 说明 |
|------|------|------|
| 频率 | 10 kHz | DRV8833 推荐范围 |
| 分辨率 | 8-bit (0-255) | 精度足够 |
| 通道 | 4 (AIN1/AIN2/BIN1/BIN2) | 双电机各两相 |

#### 4. FreeRTOS 任务影响

| 项 | 说明 |
|----|------|
| 任务名 | `motion_task` |
| 优先级 | 3 (中) |
| 栈大小 | 2 KB |
| 核心 | Core 1 |
| 周期 | 10ms (100 Hz) |
| 输入 Queue | `xQueueMotion` — 接收运动命令 |
| 输出 | LEDC PWM 控制电机 |

#### 5. 云/网络依赖

无直接依赖。运动命令由行为系统本地生成。

#### 6. 异常处理

| 异常 | 处理策略 |
|------|---------|
| 红外避障触发 | 立即 STOP，后退 1 秒，通知行为系统 |
| 边缘检测触发 | 立即 STOP，后退 2 秒，通知行为系统 |
| 电机堵转 | 超时检测 (500ms 无编码器变化)，STOP 并告警 |
| 低电量 (<3.3V) | 禁止运动命令，仅允许基本表情 |
| 运动命令 Queue 溢出 | 丢弃旧命令，执行最新命令 |

#### 7. 验收条件

| # | 条件 | 测试方法 |
|---|------|---------|
| AC-01 | 前进/后退/转向/原地旋转命令执行正确 | 逐个发送命令，观察电机运动方向 |
| AC-02 | 速度控制线性可调 | PWM 0→255 渐变测试 |
| AC-03 | 响应延迟 ≤ 10ms | 从发送 Queue 命令到 PWM 输出变化 |
| AC-04 | 急停命令立即生效 | 高速运行时发送 STOP，<10ms 停止 |
| AC-05 | 避障传感器触发时自动停止 | 手动遮挡红外，验证急停 |
| AC-06 | 边缘检测触发时自动停止 | 模拟桌面边缘信号，验证后退 |

### FR-04: 传感器系统

#### 1. 功能描述

| 项 | 说明 |
|----|------|
| **做什么** | 采集 IMU 姿态数据、红外避障/边缘检测信号、电池电压 |
| **触发条件** | 定时轮询 (50ms 周期) + GPIO 中断 (红外) |
| **期望结果** | 传感器数据通过事件总线分发到行为系统和运动控制 |

#### 2. MVP 传感器清单

| 传感器 | 接口 | 采集方式 | 数据 | 用途 |
|--------|------|---------|------|------|
| MPU6050 (IMU) | I2C | 轮询 20Hz | 加速度+角速度 (6轴) | 跌落检测、姿态感知 |
| TCRT5000 ×2 (避障) | GPIO | 中断+轮询 | 0/1 (有/无障碍) | 前方障碍物检测 |
| ITR20001 ×2 (边缘) | GPIO | 中断+轮询 | 0/1 (有/无边缘) | 桌面边缘防跌落 |
| 电池电压 | ADC | 轮询 1Hz | 电压值 (mV) | 电量监测 |

#### 3. 硬件依赖

| 硬件 | 型号 | 接口 | 状态 | 说明 |
|------|------|------|------|------|
| IMU | MPU6050 | I2C @ 400kHz | BSP 已初始化总线 | 地址 0x68，需添加设备驱动 |
| 红外避障 | TCRT5000 ×2 | GPIO 14/15 | BSP 已初始化 | 输入+上拉 |
| 红外边缘 | ITR20001 ×2 | GPIO 16/17 | BSP 已初始化 | 输入+上拉 |
| 电池 ADC | GPIO 1 | ADC1_CH0 | BSP 已初始化 GPIO | 需配置 ADC oneshot driver |

#### 4. FreeRTOS 任务影响

| 项 | 说明 |
|----|------|
| 任务名 | `sensor_task` |
| 优先级 | 2 (低) |
| 栈大小 | 2 KB |
| 核心 | Core 1 |
| 周期 | 50ms (20 Hz) |
| 输入 | I2C 读 MPU6050 + GPIO 读红外 + ADC 读电压 |
| 输出 | `xQueueSensorData` — 传感器数据广播 |

**中断处理：**

| 中断 | GPIO | 优先级 | 处理 |
|------|------|--------|------|
| 红外避障 | 14/15 | 高 | ISR 置标志 → sensor_task 处理 |
| 红外边缘 | 16/17 | 高 | ISR 置标志 → sensor_task 紧急 STOP |

#### 5. 云/网络依赖

无直接依赖。传感器数据全部本地处理。

#### 6. 异常处理

| 异常 | 处理策略 |
|------|---------|
| MPU6050 I2C 通信失败 | 重试 3 次，仍失败则标记 IMU 故障，禁用跌落检测 |
| 红外传感器常亮/常灭 | 标记传感器故障，日志告警，降级运行 |
| ADC 读数异常 (<2.5V 或 >4.5V) | 标记 ADC 故障，使用默认值，禁用低电量保护 |
| 传感器数据异常值 | 低通滤波 + 中值滤波，过滤尖峰 |
| 所有传感器同时故障 | 进入安全模式：禁止移动，仅显示表情 |

#### 7. 验收条件

| # | 条件 | 测试方法 |
|---|------|---------|
| AC-01 | MPU6050 正确读取加速度和角速度 | 静止时读取重力 ≈ 9.8 m/s² |
| AC-02 | 红外避障检测距离 2-15cm | 物体遮挡/移除，验证 GPIO 状态变化 |

## 8. 验收检查表

### 8.1 Requirement Skill Checklist

- [x] **硬件能力是否满足需求？** — ESP32-S3 16MB Flash / 8MB PSRAM / 双核 240MHz / 内置 WiFi 足够
- [x] **实时性是否能保证？** — 音频高优先级 (8/7)，显示 (6)，运动 (3)，行为 (1)，合理分配
- [x] **功耗影响是否可接受？** — 峰值 ~1100mA，活跃 ~500mA，估算续航 5.2h (≥4h 目标)
- [x] **是否有离线降级方案？** — WiFi 断开时：本地唤醒词 + 预设表情 + 基础移动 + ERROR 提示
- [x] **边界条件是否覆盖？** — 低电量/网络断开/传感器故障/API 限流/内存不足均有处理
- [x] **安全风险是否考虑？** — API Key NVS 加密/HTTPS/TLS/OTA 签名/语音数据不存储
- [x] **依赖是否明确？** — 硬件选型确定，云端 API 确定 (Claude/GPT/DeepSeek)，第三方库依赖 IDF
- [x] **验收条件是否明确可测？** — 每个功能模块有具体 AC 编号和测试方法
